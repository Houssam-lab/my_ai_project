# خطة إخراج المستودع من فوضى Vibe Coding

## النطاق الحاكم

هذه الخطة لا تعيد فتح المنصة التعليمية ولا تنقل خدماتها. وفق D-300، المسار النشط
الوحيد هو أداة تنظيف مراجع الفوترة الفرنسية/البلجيكية (`tools/hard_currency_engine`)،
مع إبقاء CI صادقًا. الوحدات القديمة `CBAM` و`ZATCA` و`EAA` تبقى على القرص للتاريخ،
لكنها ليست جزءًا من مسار العميل.

## خط الأساس المقاس

- المستودع يحتوي على طبقات كثيرة (`app/` و`microservices/` و`frontend/`) لكنها مجمّدة؛
  لذلك لا نزيد سطح التغيير في هذه المرحلة.
- بيئة التشغيل المحلية الحالية Python 3.11، بينما العقد يطلب Python 3.12+؛ لا يجوز
  اعتبار فحص `compileall` المحلي الكامل بديلاً عن CI على 3.12.
- اختبار HCE الموجود شغّل 39 اختبارًا ونجح محليًا.
- أضيفت بوابة مستقلة تتحقق من: قابلية ترجمة وحدات HCE، حدود أوامر CLI الثلاثة،
  وعدم استيراد الوحدات المسحوبة من واجهة العميل.

## دورة التغيير الإلزامية

1. **خطة:** حدّد مشكلة عميل حقيقية، عقد الإدخال/الإخراج، ومخاطر الفشل قبل الكود.
2. **تصميم:** كل ممر (France/Belgium/CRM) يظل خلف دوال خدمة؛ لا منطق تجاري في
   بوابة CLI. أي قرار معمارِي جديد يحتاج ADR.
3. **تنفيذ صغير:** تغيير واحد قابل للعكس، دون خلطه بإعادة تنسيق أو نقل ملفات.
4. **اختبار:** اختبار وحدة لكل قاعدة تحقق، اختبار تكامل للـ CSV، واختبار CLI للعقد؛
   لا تعتمد على اختبار شبكة حية، بل استخدم بدائل محقونة وفشلًا صريحًا عند انقطاعها.
5. **مراجعة:** لا دمج إلى `main` دون مراجع ثانٍ؛ يراجع المراجع الحدود، الرسائل،
   الخصوصية، وعدم تحويل «غير متاح» إلى «صالح».
6. **تسليم آمن:** CI يشغل البوابة والاختبارات على Python 3.12؛ الفشل يوقف الدمج.
   لا يوجد نشر تلقائي لأداة تنشئ مخرجات موجهة لعميل.
7. **استرجاع:** `git revert` هو المسار الافتراضي. لا تعديل للبيانات أو الهجرات في
   هذا المسار. أي فشل في CI يمنع التسليم ولا يُتجاوز بتعطيل الاختبار.

## تعريف الجاهزية

- **Build:** وحدات HCE قابلة للترجمة على Python 3.12.
- **Tests:** كل اختبارات HCE والبوابة خضراء، ولا توجد اختبارات شبكة غير حتمية.
- **Security:** لا أسرار في المستودع، ولا إرسال بريد فعلي من `crm`؛ المخرجات مسودات.
- **Observability:** تقرير JSON/Markdown يذكر وقت التشغيل وحالة عدم توفر الشبكة بدل
  ادعاء المطابقة.
- **Review:** مراجع مستقل وقرار قبول موثق في PR.
- **Rollback:** تغيير صغير قابل للعكس مع عدد حذف يساوي صفرًا.

## مؤشرات يومية

| المؤشر | الإجراء عند الانحراف |
|---|---|
| نجاح بوابة HCE | إيقاف الدمج وإصلاح السبب، لا إعادة تشغيل بلا تفسير |
| نجاح الاختبارات | فتح عيب مع اختبار إعادة إنتاج قبل الإصلاح |
| زمن CI | التحقيق في التباطؤ بدل حذف الاختبارات |
| الوحدات المسحوبة المستوردة من CLI | فشل فوري؛ لا تُعاد إلى مسار العميل دون قرار ومقارنة رسمية |
| مخرجات CRM المرسلة فعليًا | يجب أن تبقى صفرًا؛ الإرسال البشري وحده يسجل في دفتر الاتصالات |
| عدد الحذف في التغيير | صفر؛ أي استثناء يتطلب قرارًا منفصلًا |

## ما لن نفعله

لن نعيد كتابة `app/` أو `microservices/`، ولن نضيف نموذجًا أو خدمة أو تبعية خارجية
لمجرد تحسين شكلي. السرعة المقبولة هنا هي تغييرات صغيرة قابلة للقياس، لا تراكم كود
«يعمل على جهازي».
